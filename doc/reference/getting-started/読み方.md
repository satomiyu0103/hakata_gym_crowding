# コードの読み方（初心者向け）

博多混雑 RPA のソースを初めて読むときの手順。

## 1. 全体地図を読む

[`src/hakata_gym_crowding/cli.py`](../../src/hakata_gym_crowding/cli.py) のファイル冒頭（モジュール docstring）に、**番号付きの処理の流れ** がある。ここがプログラム全体の地図。

各ステップには「失敗したらどうなるか」も書いてある（例: 終了コード 0 / 1、続行するか）。

## 2. 気になるステップのファイルを開く

| 手順（cli.py） | 主なファイル |
|---|---|
| 設定読込 | `config.py` |
| 開館判定 | `schedule/guard.py` |
| 混雑取得 | `fetch/pcounter.py` |
| 天気取得 | `fetch/training_page.py` |
| Sheets 追記 | `store/sheets.py` |
| エラー通知 | `notify/slack.py` |
| 行データ組立 | `domain/record_format.py` |

## 3. D形式解説を横に開く

英語の変数名・関数名が分かりにくいときは、[d-format/](d-format/README.md) の同じトピックの MD を開く。日本語の変数名と行コメントで同じ処理を書いてある。

索引: [コード解説.md](コード解説.md)

## 4. コメントの3層を意識する

| 層 | どこ | 何が書いてあるか |
|---|---|---|
| **L1** | ファイル冒頭 | このファイルの役割と処理の大枠 |
| **L2** | 関数の直前 | 受け取る値・返す値・失敗時の扱い |
| **L3** | `if` / `for` / `try` の直前 | 条件と結果（分岐・例外） |

`try` の直前には、成功時と失敗時の行き先が箇条書きで書いてあることが多い。
