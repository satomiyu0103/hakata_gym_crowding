# 試験実装のエラー記録

## 目的

実装中に発生したエラーとその対策を記録する。着手前に必読。

「すべてのエラー」を書く帳ではない。**同じ症状が再発しうるもの**だけを残し、人と AI の認知負荷を下げるためのナレッジとする。

---

## 記載する条件（再利用価値のライン）

次のいずれかに当てはまるときは **記載する**。

| 条件 | 説明 |
|---|---|
| 再現しうる | 環境・手順・設定を変えると同じ症状が出る |
| 原因が非自明 | ログ・スタックトレースだけでは直感で分からなかった |
| 調査に時間がかかった | 目安: 15 分以上かかった、または複数の切り分けが必要だった |
| プロジェクト固有 | このリポジトリの構成・依存・規約に紐づく（汎用ドキュメントに載っていない） |
| 再発防止できる | ルール・チェック・テンプレ修正など、**次に防ぐ具体策**を書ける |

### 記載しない（または Issue だけで足りる）

| 対象 | 理由 |
|---|---|
| タイポ・未保存・パス打ち間違い | 再利用価値がほぼない |
| すぐ直った単純な構文・import 漏れ | エディタや linter で防げる |
| 個人 PC だけの一時障害（再起動で解消） | 他メンバーに再現しない |
| 秘密情報の混入 | 値は書かず、`.gitignore` や運用で防ぐ（ログに鍵を残さない） |

迷ったときは **「1 週間後の自分／他の開発者が同じハマりをするか？」** で判断する。Yes なら記載、No なら省略でよい。

### 他ドキュメントとの役割

| 書く場所 | 向き |
|---|---|
| **このファイル** | 症状・原因・対策・再発防止（ナレッジ） |
| `doc/specs/07_CHANGELOG.md` | リリース単位で「何を直したか」（`Fixed` + FR コード） |
| GitHub Issue / PR | 再現手順・議論・レビュー。長い調査はここに詳細を書き、このファイルには要約とリンク |

```
### [YYYY-MM-DD] エラーの概要（1行）

**原因**: なぜ起きたか
**対策**: どう解決したか
**再発防止**: 同じミスを防ぐために何をするか
```

### [2026-08-15] OS 予約キー（PrintScreen）とグローバルホットキーの競合

**症状**: 利用者が PrintScreen 等をホットキーにすると、OS 標準機能（例: Snipping Tool）が同時に起動する。抑止するとアプリ側の撮影も動かない場合がある

**対策**: MVP では競合の少ないキー（F1〜F12 等）に限定。OS 予約キーは要件で Wont とする  
**再発防止**: [desktop-windows-mvp-spec-gates.md](desktop-windows-mvp-spec-gates.md) §2。実装前に ADR で Go/No-Go

**症状**: 撮影は成功するが、ブラウザ等の対象アプリがページ送り等に反応しない

### [2026-09-05] Ruff DTZ005 — datetime.now() に tz 必須

**症状**: Ruff が `datetime.now()` に `Pass a datetime.timezone object to the tz parameter`（DTZ005）を指摘する  
**原因**: タイムゾーンなしの「今」は OS ローカル依存で曖昧。Ruff は aware な時刻を要求する  
**対策**: `datetime.now(tz=UTC)` に統一。JSON への isoformat 保存・fromisoformat 読み込み・経過時間比較も同じ基準に揃える  
**再発防止**: テストだけ `tz=` を付けると、本番が naive のままだと `datetime.now() - last_sent` で TypeError。修正時は「書き込み・読み込み・比較」の3点をセットで確認する。既存 state に naive 文字列が残る場合は `replace(tzinfo=UTC)` で後方互換を取る  

関連: `tests/test_slack_notify.py` · `src/hakata_gym_crowding/notify/slack.py`（FR-LOG-002 重複抑制）

### [2026-09-05] gspread ValueInputOption — 型チェッカーが文字列を拒否

**症状**: `Worksheet.append_row` の `value_input_option="USER_ENTERED"` に対し、型チェッカーが `Expected ValueInputOption, found Literal["USER_ENTERED"]` を出す  
**原因**: gspread の型定義（スタブ）では `value_input_option` は **列挙型（enum）** を要求する。文字列 `"USER_ENTERED"` は実行時は通るが、型の上では別物として扱われる  
**対策**: `from gspread.utils import ValueInputOption` を import し、`value_input_option=ValueInputOption.user_entered` を渡す（メンバー名は小文字の `user_entered`）  
**再発防止**: 外部ライブラリの kwargs で英語リテラルを渡す前に、公式の enum / 定数があるか確認する。行データの型エラー（`None` 混入）も同時に出ることがある → 返り値の型注釈を実際の値（空文字変換後）に合わせる  

関連: `src/hakata_gym_crowding/store/sheets.py` · `src/hakata_gym_crowding/domain/record_format.py`

### [2026-09-05] Ruff I001 — import 行の並び・折り返し

**症状**: Ruff が `Import block is un-sorted or un-formatted`（I001）を指摘する  
**原因**: import の順序・グループ分け、または 1 行が長すぎて複数行に折り返すべきと isort ルールが判断した  
**対策**: `uv tool run ruff check <file> --select I --diff` で期待形を確認し、長い import は括弧で複数行にする  
**再発防止**: 保存時の organize imports と Ruff I001 を同じ基準に揃える。修正後は `--select I` で再確認  

関連: `src/hakata_gym_crowding/store/sheets.py`

### [2026-09-05] Ruff DTZ007 — strptime で naive datetime が生成される

**症状**: Ruff が `datetime.strptime(...)` に `Naive datetime constructed ... without %z`（DTZ007）を指摘する。ヒントは `.replace(tzinfo=...)` または `.astimezone()`  
**原因**: フォーマット文字列に `%z`（タイムゾーンオフセット）が無いため、パース結果はタイムゾーンなし（naive）の `datetime` になる。本プロジェクトは `CrowdingSnapshot.recorded_at` を JST aware で扱う前提（`cli.py`・`pcounter.py`・テスト）  
**対策**: `record_format.py` の旧6列移行パースで `strptime` 後に `.replace(tzinfo=ZoneInfo("Asia/Tokyo"))` を付与。モジュール定数 `_LOCAL_TZ` で共通化  
**再発防止**: シート由来の日時文字列（オフセット無し）をパースする箇所は、必ずプロジェクト既定 TZ（`Asia/Tokyo` または `settings.timezone`）を明示する。`strptime` だけで終わらせない  

関連: `src/hakata_gym_crowding/domain/record_format.py` · `tests/test_migrate_sheet_columns.py`

### [2026-09-05] 戻り値型 — `list[str | int | None]` と実値の不一致

**症状**: 型チェッカーが `Return type does not match returned value: expected list[str | int | None], found list[str | int]` を指摘する（`convert_legacy_row` → `record_to_row`）  
**原因**: `convert_legacy_row` の戻り値型に `None` が含まれていたが、`record_to_row` は天気列などの欠損を `None` ではなく空文字 `""` に変換するため、実際のリスト要素は `str | int` のみ  
**対策**: `convert_legacy_row` の戻り値型を `list[str | int]` に修正（`record_to_row` と同型に揃える）  
**再発防止**: シート行用の変換関数は「`None` を返す」か「空文字に潰す」かを先に決め、戻り値型注釈をその実装に合わせる。委譲（別関数の return をそのまま返す）時は、下位関数の型と一致させる  

関連: `src/hakata_gym_crowding/domain/record_format.py` · 同ファイルの gspread エントリ（L120）と同種の型注釈ずれ

### [2026-09-10] スリープ中に初回トリガーを逃すと当日の定期実行が全日停止する

**症状**: 手動実行（デスクトップ BAT / `Start-ScheduledTask`）では `logs/run.log` に `ok` が追記されるが、当日は 9:00 以降の定期実行が一切増えない。タスクスケジューラの **見逃しされたタスクの数** が 26（9:00〜21:30 の 30 分間隔・1 日分）になる。`run.log` に当日分が 1 件だけ（手動実行の :34 など :00/:30 以外の時刻）ある場合もある  
**原因**: 次の 3 点が重なる。

1. **PC スリープ** — 当日 9:31 頃までスリープしていた場合、9:00・9:30 のトリガーは起動しない（`WakeToRun` は PC を起こすが、下記 2 と組み合わさる）
2. **ログオン種別 Interactive** — タスク `HakataGymCrowding` が「ユーザーがログオンしているときのみ」だと、スリープ解除直後・ログオン前は実行されない
3. **繰り返しトリガーの挙動** — 毎日 9:00 開始・30 分間隔・13 時間の **初回（9:00）を逃した日**は、`StartWhenAvailable`（スケジュールされた時間にタスクを開始できなかった場合、できるだけ早く開始）が ON でも **当日の残り 25 回を自動で埋めない**。ログオン後に PC が起きていても 10:00 以降の繰り返しが再開しないことがある

RPA 本体・Sheets・取得 API は正常。休館日（`ScheduleGuard`）でもない  
**調査手順**:

```powershell
# タスク状態
Get-ScheduledTaskInfo -TaskName "HakataGymCrowding" |
  Format-List LastRunTime, LastTaskResult, NextRunTime, NumberOfMissedRuns

# 当日の run.log（:00/:30 以外の時刻は手動実行の疑い）
Get-Content logs\run.log -Tail 30

# スリープ復帰（当日分）
Get-WinEvent -FilterHashtable @{
  LogName = 'System'; ProviderName = 'Microsoft-Windows-Power-Troubleshooter'
} -MaxEvents 20 | Where-Object { $_.TimeCreated.Date -eq (Get-Date).Date }
```

**対策**（いずれか・併用可）:

| 優先 | 案 | 内容 |
|---|---|---|
| A | **運用** | **毎日 9:00 前に PC を起動しログオン**する。初回トリガーを逃さないのが最も確実 |
| B | **ログオン時セーフティネット** | ユーザーログオン時に 1 回だけ CLI を走らせる別タスクを追加（下記 PowerShell 例） |
| C | **ログオン種別変更** | タスクを「ユーザーがログオンしているかどうかにかかわらず実行」に変更（パスワード保存が必要） |
| D | **クラウド移行** | PC 常時起動を避ける — [cloud-github-actions-migration.md](../../specs/plans/cloud-github-actions-migration.md) |

ログオン時 1 回実行の登録例:

```powershell
$repo = "D:\pc_handover_2026-07\Documents\Development\RPA_scripts\hakata_gym_crowding"
$uvPath = (Get-Command uv).Source
$action = New-ScheduledTaskAction `
  -Execute $uvPath `
  -Argument "run python -m hakata_gym_crowding.cli" `
  -WorkingDirectory $repo
$trigger = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries
Register-ScheduledTask `
  -TaskName "HakataGymCrowding_LogOnCatchUp" `
  -Action $action -Trigger $trigger -Settings $settings `
  -Description "博多混雑 RPA — ログオン時 1 回（スリープ取りこぼし救済）"
```

**再発防止**: [windows-scheduled-sync.md](../../reference/setup/windows-scheduled-sync.md)「定期実行の前提・トラブルシュート」に運用要件を明記。`NumberOfMissedRuns` が 20 超ならスリープ／初回トリガー逃しを疑う  
**関連**: インシデント記録 [sessions/2026-09-10_scheduler-sleep-missed-runs.md](../sessions/2026-09-10_scheduler-sleep-missed-runs.md) · タスク名 `HakataGymCrowding`
