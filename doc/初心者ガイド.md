# 初心者ガイド — このテンプレの使い方

AI 駆動開発を初めて使う利用者向けに、**何が入っているか**と**Cursor での頼み方**だけに絞って書いています。

環境構築の詳細は [doc/reference/README.md](reference/README.md)。エージェント向け索引は [AGENTS.md](../AGENTS.md)。

---

## 1. このテンプレは何？

**AI（Cursor）に渡す「開発のルールブック一式」** です。

毎回チャットで同じ注意（ブランチの切り方、CHANGELOG の書き方、テストの有無）を繰り返さず、**やり方をそろえる** ための土台です。特定の言語やフレームワークに縛られません（Python / GAS / その他をプロジェクトで選びます）。

---

## 2. フォルダのイメージ（これだけ覚えれば OK）

```
src/ または gas/   … 実装本体（スタック選定後）
doc/specs/         … 何を作るか（要件・設計・CHANGELOG）
doc/ai/sessions/   … なぜそうしたか（意思決定の記録）
doc/reference/     … セットアップ手順・早見表
.cursor/rules/     … 常時・実装時のルール
.cursor/skills/    … Phase・監査などの詳細手順
```

| やること | 置き場所 |
|---|---|
| 要件・機能 ID・変更履歴 | `doc/specs/` |
| 設計判断の経緯 | `doc/ai/sessions/` |
| 環境構築 | `doc/reference/setup/` |
| 実装コード | `src/` または `gas/`（プロジェクトで決定） |

---

## 3. 中身の種類（全部覚えなくてよい）

| 種類 | 場所 | 役割 |
|---|---|---|
| ルーター | `AGENTS.md` | 「今何をする？」→ どの skill / rule を見るか |
| 常時ルール | `.cursor/rules/agent_core.mdc` 等 | 禁止事項・CHANGELOG 義務など |
| Phase 手順 | `.cursor/skills/implementation-phase*` | 着手前・実装中・完了後の読む順序 |
| 監査 | `.cursor/skills/audit-*` | 品質チェック（種別ごと） |
| 利用者向け手順 | `doc/reference/` | セットアップ・Git 早見表など |

**初心者が最初に使うのは Phase 1〜3 と `doc/reference/getting-started/` で十分** です。

---

## 4. Cursor への頼み方（コピペ用）

チャットに **skill 名や Phase** を書くのがコツです。

### よく使う依頼文

| やりたいこと | Cursor に貼る文 |
|---|---|
| 機能を実装する | `implementation-phase1 skill に従って、（機能）の実装を始めて` |
| 実装中の確認 | `implementation-phase2 skill に従って進めて` |
| 完了・doc 更新 | `phase3-doc-updates skill で CHANGELOG と sessions を更新して` |
| 価値があるか検証 | `task-value-first skill で、この変更の要否を確認して` |
| CHANGELOG だけ | `changelog-entry skill で今回の変更を CHANGELOG に追記して` |
| 品質監査 | `audit-implementation skill で実装を監査して` |

### 例

```text
implementation-phase1 skill に従って、doc/specs/02_要件定義.md の FR-XXX を実装して。
ブランチは git_workflow に従って切って
```

```text
phase3-doc-updates skill で、今回の実装を CHANGELOG と doc/ai/sessions/ に記録して
```

## 5. おすすめの進め方（3 段階）

### 段階 A: テンプレを読むだけ

1. このファイルと [AGENTS.md](../AGENTS.md) をざっと読む
2. [getting-started/入門ガイド.md](reference/getting-started/入門ガイド.md) でフォルダの意味を確認
3. 採用スタックの [setup/](reference/setup/) を 1 本だけ読む

### 段階 B: 小さな変更を試す

1. `doc/specs/02_要件定義.md` を開き、1 機能だけ選ぶ
2. `git_workflow` に従いブランチを切る
3. Phase 1 → 2 → 3 で実装・記録する

### 段階 C: 本番プロジェクトへ展開

1. 業務リポジトリにテンプレをコピーまたは `template_sync` で同期
2. `doc/specs/` をプロジェクト内容に書き換える
3. [doc/reference/getting-started/入門ガイド.md](reference/getting-started/入門ガイド.md) のプレースホルダを埋める
