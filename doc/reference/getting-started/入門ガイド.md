## 2. フォルダ構成の意味

| フォルダ | 役割 |
|---|---|
| `src/` | 実際に動くプログラム本体（スタック選定後に構築） |
| `tests/` | 動作確認コード |
| `doc/` | 仕様・設計・開発ルール・意思決定の記録 |
| `config/` | ローカル設定（`.env` など、Git 除外） |
| `data/` | 実行時に生成されるデータ（Git 除外） |
| `logs/` | 実行ログ出力先（Git 除外） |

## 3. 意思決定はどこに残すか

実装や設計の **なぜ** はチャットだけに残さず、次に記録します。

| 記録 | 場所 |
|---|---|
| 日次サマリ | `doc/specs/00_開発日誌.md` |
| 経緯・採用/非採用の本文 | `doc/ai/sessions/` |
| トピック横断の索引 | `doc/ai/decisions/README.md` |

詳細: [doc/ai/sessions/README.md](../../ai/sessions/README.md)

## 4. レイヤの考え方（役割分担）

<!-- プロジェクトのレイヤ構成に合わせて書き直す -->

| レイヤ | 責務 |
|---|---|
| `domain/` | ビジネスロジック。外部依存なし |
| `clients/` | 外部 API への接続処理 |
| `infra/` | 設定読み込み・ログ・状態保存などの土台 |
| `service/` | 各部品をつないで処理を実行する司令塔 |
| `cli/` / `api/` | コマンド or リクエストを受け取り実行開始 |
