## アーキテクチャ概要

```
GitHub Actions
  (9:00–21:30 JST / 30分)
        │
        ▼
  hakata_gym_crowding.cli
        │
        ├─ ScheduleGuard ── skip (休館/時間外)
        │
        ├─ PCounterFetcher ── GET JSON ×2
        │
        ├─ TrainingPageFetcher ── GET HTML（天気6項目）
        │
        ├─ crowding_level ── 人数→4段階
        │
        ├─ record_format ── 16列レコード組立
        │
        └─ SheetsWriter ── スプレッドシート追記
                │
                ├─ logs/run.log
                └─ notify/slack ── ERROR 時 Webhook（任意）
```

## スプレッドシート列（混雑履歴・16列）


| # | 列 | 型 | 内容 |
|---|---|---|---|
| 1 | 日付 | 文字列 | 取得日（JST） |
| 2 | 曜日 | 文字列 | 月〜日 |
| 3 | 取得時間 | 文字列 | RPA 実行時刻 |
| 4 | 計測時間 | 文字列 | JSON `time_calc` |
| 5 | 天気 | 文字列 | 晴れ・曇り等 |
| 6 | 最高気温 | 数値 | ℃ |
| 7 | 最低気温 | 数値 | ℃ |
| 8 | 風速 | 数値 | m/s |
| 9 | 風向 | 文字列 | 東など |
| 10 | 降水確率 | 数値 | 0〜100 |
| 11 | ステータス | 文字列 | OK / stale_data / maintenance 等 |
| 12 | トレーニングルーム利用者数 | 数値 | JSON `sum.area1` |
| 13 | 混雑レベル | 文字列 | 4段階 |
| 14 | 体育館利用者数 | 数値 | JSON `sum.area1`（gym） |
| 15 | イベント | 文字列 | 将来用（初期は空欄） |
| 16 | 備考 | 文字列 | stale・天気失敗の注記 |

分析の時間軸は **計測時間** を主に使う。取得時間は Scheduler 監査用。

旧6列（英語ヘッダー）からの移行: `scripts/migrate_sheet_columns.py`

## 休館・実行時間（ScheduleGuard）

1. JST 9:00 ≤ 現在 < 22:00 以外 → 実行しない（Sheets 非記録）
2. 毎月第3月曜 → 休館
3. 第3月曜が祝日 → 翌火曜も休館（`jpholiday`）
4. 12/28〜1/4 → 休館
5. JSON `special_holiday` → MVP では未使用

## セキュリティ・運用

- 秘密情報は `config/.env` と `config/service-account.json`（Git 除外）。クラウド実行時は GitHub Secrets から同等のファイルを生成する
- HTTP: タイムアウト 30 秒、指数バックオフリトライ（最大3回）
- stale 判定: `time_calc` が現在から5分以上離れていれば `stale_data`（記録は行う）
- maintenance 時は Sheets へ書き込まない
- Slack 通知: `SLACK_WEBHOOK_URL` 設定時のみ ERROR（config / fetch / sheets）を Incoming Webhook へ送信。同一 stage は 15 分以内 1 回。通知失敗でも CLI の exit code は変えない。Webhook URL・認証情報はログ・通知本文に含めない
